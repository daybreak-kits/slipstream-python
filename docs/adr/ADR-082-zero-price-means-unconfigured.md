# ADR-082 单价 0 = 未配置（不支持显式标价 0）

- 状态：accepted（2026-11-18）
- 关联：ADR-073（模型默认参数同步——models.dev 价格只是默认值）、ADR-077（成本优先策略）、GLOSSARY「未配置单价」「成本口径」、`docs/ui.md` §2.4

## 背景

全站审计发现同一事实在三处的表现互相矛盾：渠道模型以 0 存单价时，模型管理价格列渲染「入 $0.00 / 出 $0.00」、渠道模型映射单价列同样、日志失败行费用列渲染 `$0.00`——而日志详情抽屉、试验页统计行、看板成本磁贴显示「未配置单价」。`$0.00` 会被读成"这些调用是免费的"，正是 `format.ts:44` 注释里早已写明的顾虑。

事实核查：计费层 `billing.py` 以 `float(price or 0)` 取值——**0 与未配置在计费上不可区分**；`channel_models` 价格列 NOT NULL 默认 0；展示层 `format.ts` 已有口径「有词元消耗而成本为 0 ⇒ 判为未配置」；GLOSSARY 成本优先策略词条「未配置价格的成员按 0（免费）参与」。三处现状事实上已经选择了"0 = 未配置"，只有两个展示面与编辑表单（预填 0）没有对齐。

## 决策

1. **单价 0 的正式语义 = 未配置**。系统不支持"显式标价 0 的免费模型"；计费按 0、展示按未配置口径（`format.ts` 既有判断），两个违例展示面向其对齐。
2. **编辑表单不预填 0**：价格输入框留空 + 说明留空语义（与缓存价「留空 = 按输入价」同款）；留空提交按 0 存储，语义与现状兼容，零 schema/API 变更。
3. **免费模型留给未来**：若确有"显式标价免费"的需求，走价格列 nullable 的独立变更（需同步计费层与展示层三分支），届时另立 ADR；当前无此需求，不做。
4. 排序语义不变：成本优先策略中未配置成员继续按 0 参与（ADR-077 既有裁决，GLOSSARY 措辞同步去掉"（免费）"括注以免与展示口径撞车）。

## 理由

- 备选"引入 nullable 价格列区分免费与未配置"被否：三处现状（计费、格式化、词义）已一致按"0=未配置"运作，改存储是三倍工程量；且"标价免费"当前是假想需求（YAGNI）。
- 备选"仅修展示不动表单"被否：表单预填 0 是违例数据的持续来源，只修显示会在下一次编辑后回潮。

## 后果与影响

- 修复批次第一批：模型管理价格列、渠道模型映射单价列、日志失败行费用列改走 `format.ts` 口径；模型编辑表单价格字段留空化；失败请求的首字/首答耗时同样按"无数据 → —"处理（同口径族）。
- 真实成本为 0 的空请求（tokens=0）不受影响：启发式只在"有词元消耗且费用为 0"时触发。
- 词义表新增「未配置单价」词条，措辞与 ADR-082 锁定。
