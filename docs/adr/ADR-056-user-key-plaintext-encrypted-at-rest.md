## 背景

## 决策

用户密钥明文加密留存，可复制可重置

## 理由

压缩表没有把「理由」与「后果」分开记，当时的评价都写在同一栏里，原文见「后果与影响」；此处不另作解释。

## 备选与否决原因

当时未记录备选方案与否决原因（压缩表只保留结论）。

## 后果与影响

2026-11-14 新增；`api_keys.key_enc`（Fernet，复用渠道密钥基建）存加密明文，列表随时可复制（`GET /api/keys/{id}/secret`，旧数据无 key_enc 时提示先重置）；行内「重置」生成新明文并立即作废旧密钥（`POST /api/keys/{id}/reset`）；鉴权依据仍是 `key_hash`，明文泄露风险由加密列与「怀疑泄露即重置」流程兜底；试验页配套把密钥改回内存态输入，满足「拿不同密钥测试」的需求
